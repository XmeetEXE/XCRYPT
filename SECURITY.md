# Security Policy

## Supported version

Security fixes are intended for the latest published release on the `main` branch. Older releases may not receive updates.

## Reporting a vulnerability

Please do not disclose vulnerabilities publicly before a fix or coordinated disclosure plan is available. Until a dedicated security contact is published, contact the repository owner privately through the contact method listed on their GitHub profile. Include the affected version, environment, reproduction steps, impact, and any proposed mitigation. Do not include real secrets or other people's data.

Please allow reasonable time to investigate and prepare a fix. This project is maintained on a best-effort basis and does not promise a particular response or resolution time.

## Scope and safe testing

Only test copies of XCRYPT that you own or have explicit permission to assess. Do not test against other users, systems, or networks. Avoid destructive testing and do not access, modify, or retain other people's information.

## Security expectations

XCRYPT is not independently audited. A security report is welcome, but a successful test or the use of a standard algorithm should not be interpreted as proof that the complete application is secure.
